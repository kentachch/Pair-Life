# MVP後の開発計画

MVPリリース後に追加したい機能をまとめます。

## 追加予定の機能

### 1. レシート撮影による支出入力(OCR)(#23)

レシートを撮影すると、金額・日付・店名などを自動で読み取り、支出フォームに反映する機能です。

- **流れ**:撮影して送信 → 読み取り結果をフォームの初期値として表示 → ユーザーが確認・修正 → 保存
- OCRは必ず読み間違いが起きるため、**確認画面を必ず挟む**
- 撮影したレシート画像は Active Storage で保存し、後から見返せるようにする
- 技術の選択肢は、Google Cloud Vision などの専用OCRサービスか、画像を扱えるAIのAPIに項目の抽出を依頼する方法。日本語のレシートは後者のほうが精度・実装の手軽さで有利なことが多い
- 本番環境では画像の保存先を S3 などのクラウドストレージに切り替える設定が必要

### 2. 支出の小分類(#24)

現在のカテゴリー(家賃・水道代・電気代・ガス代・食費・日用品・外食・雑費・交際費・その他)の下に、小分類(野菜、魚など)を追加します。

- categories テーブルに `parent_id` を追加することで対応できる設計になっている

### 3. Googleログイン

メールアドレスとパスワードに加え、外部サービスでのログインに対応します。

- `omniauth` 系のGemで追加できる
- **Googleログインは実装済み**(`omniauth-google-oauth2`)。LINEログインは実装しない

### 4. 負担割合の変更(#26)

収入に応じて6:4にするなど、50-50以外の割合を設定できるようにします。

- household_members の `burden_ratio` カラムと、割合に対応した精算ロジックは実装済み
- 変更画面と、2人の割合の合計が100になっているかのバリデーションを追加する

### 5. 世帯からの退出・アカウント削除

- 退出したメンバーが登録した支出や精算記録の扱いを決める必要があり、実装は複雑になる
- アカウント削除は Devise の `registerable` に標準で含まれるが、MVPでは画面に表示しない

### 6. 買い物リストの拡張

買い物リスト(実装済み)に、次の機能を追加する案です。

- **リアルタイム更新**:Turbo Streams / Action Cable で、相手の追加やチェックを再読み込みなしで反映する
- **通知**:パートナーがアイテムを追加したときなどに知らせる
- **支出登録との連携**:「チェック済みを削除」のときに、買った物の支出を登録する形を想定

### 7. 予算の設定(#44)

予算を設定し、予算に対して今月の支出がどのくらいなのかをホームに表示します。支出の使いすぎを防ぐためです。

- 予算の単位(世帯全体の月予算か、カテゴリーごとの予算か)を決める必要がある
- 予算を保存するテーブルを新しく作る(例:`budgets` に `household_id` / `category_id` / `amount`)

### 8. メンバーごとのカテゴリー別の支出表示(#46)

支出一覧に、メンバーごとの毎月の支出の合計をカテゴリー別に表示します。今はメンバーごとの合計金額しか表示されず、どのカテゴリーにどの程度使っているのかが分かりにくいためです。

- 世帯全体のカテゴリー別合計は `Household#category_totals` で取得できるため、メンバーごとに絞る処理を追加すれば対応できる
- 表示方法は、一覧(表)か円グラフかを決める

## 着手する順番

GitHub の issue の優先度ラベル(priority1〜3)に合わせて、次の順で進めます。

1. **本番環境のメール送信設定(#47、priority1)**
   MVP の機能であるパスワード再設定が、本番環境ではメールの送信先が設定されておらず動かない可能性があります。新機能より先に直します。
2. **メンバーごとのカテゴリー別の支出表示(#46、priority2)**
   既存の集計処理(`Household#category_totals`)を使えるため、小さな変更で追加できます。
3. **精算時のメール通知(#39、priority2)**
   #47 で整えたメール送信の設定を使うため、#47 の後に着手します。
4. **priority3 の機能**は、次の順を想定します。
   1. 負担割合の変更(#26):精算ロジックは実装済みで、画面とバリデーションの追加だけで済むため
   2. レシートOCR(#23):「入力の手間」という開発当初の課題に最も直接効く機能。ただし外部 API やクラウドストレージの準備が必要で、作業量が大きい
   3. 予算の設定(#44):新しいテーブルが必要になる
   4. 支出の小分類(#24):カテゴリーの構造が変わり、集計やグラフ表示にも影響するため、ほかの集計機能がそろってから着手する
   5. 世帯からの退出・アカウント削除:影響範囲が広いため最後に回す
   6. 買い物リストの拡張:今の機能で目的(買う物を忘れない)は達成できているため最後に回す
